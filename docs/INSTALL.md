# 安装、映射与升级

## 首次安装

1. 从 [GitHub 最新发布](https://github.com/YinsenWANG/bitable-control-assistant/releases/latest) 下载名称以 `-chrome.zip` 结尾的文件，不要下载 GitHub 自动生成的 Source code。
2. 解压到一个准备长期保留的文件夹。
3. 在 Chrome 地址栏手动打开 `chrome://extensions`，开启右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的文件夹。
5. 打开飞书多维表格并刷新。扩展会自动识别页面，无需填写表格链接。

## 配置 Home 和电源

1. 在扩展设置页点击「设置电源键快捷键」或「设置 Home 键快捷键」。也可手动打开 `chrome://extensions/shortcuts`。
2. 找到「多维表格控制助手」，分别设置：
   - 电源键：刷新当前标签页（所有网站）→ **Control + Shift + 8**。
   - Home 键：回到正在会议模式的多维表格 → **Control + Shift + 0**。
3. 将遥控映射软件中的电源和 Home 设为相同组合。默认范围保持「在 Chrome 中」即可。
4. 回到设置页，它会读取 Chrome 实际保存的键值。若显示「未设置」，通常是组合被其他扩展或 Chrome 占用，请换一个 Chrome 允许的组合。
5. 在表格中开启会议后，打开一个普通网站，分别验证刷新和返回会议。

Mac 的 Control 与 Command 不可混用。Command + R 本来就能触发 Chrome 原生刷新；如果遥控器发出的原生映射不稳定，使用独立的电源命令。扩展不会在 GitHub 注入脚本或读取其内容。

## 配置其余按键

![录入、复制和原生开关](../store/keys.jpg)

![自定义缩放与原生开关](../store/settings.png)

音量默认组合为 Control + Shift + = / −，缩放使用扩展里的步长。可选的「使用原生快捷键」会显示 Command + = / −（Mac），此时直接把遥控映射为原生键，使用 Chrome 自身缩放档位；关闭开关恢复自定义键。

在「动作与快捷键」点击录入，按一次遥控按键，然后保存。每项旁的复制按钮会复制键值。按键检测区可检查是否收到按键以及是否持续连发。

建议先使用默认方向键、Enter、Backspace 和 TV，再修改菜单键等个人习惯。若开启某项「使用原生快捷键」，也要把遥控映射改为页面显示的原生组合。

语音识别沿用现有输入法：先用菜单键打开评论，按 OK 激活输入框，再按语音键输入，最后确认发送。Backspace 在输入状态只删除左侧文字，即使输入框为空、双击或长按也不会退出。菜单键可收起评论并保留草稿；Esc（「退出输入 / 逐层返回（备用）」）可以单独退出输入。非输入状态下，Backspace 才逐层收起评论、关闭详情。

### 麦克风一键接入评论（Mac，无线麦 + 微信输入法）

1. 无线麦和微信输入法保留已能正常语音输入的 **Fn** 设置，音频设备也保持一致。
2. 在扩展设置的「麦克风 · 语音接入评论」中勾选开启并保存。默认关闭，旧按键设置不会被覆盖。
3. 开启会议并打开记录详情。评论收起时，只按住遥控器麦克风说话，然后松开，不需要先按菜单或 OK。
4. 输入法完成这一段识别后，评论会自动展开，文字进入草稿。确认内容后按 OK 发送；确认发送成功后，评论默认在 1 秒后自动收起。可在扩展设置「评论发送」中关闭自动收起，或设置 0–60 秒的等待时间。期间开始输入新内容或手动操作评论时，不会自动收起。

这是接收输入法已经输出的文字，不是检测 Fn 按下；Mac Chrome 会过滤单独的 Fn 事件，因此评论不会在按下瞬间展开。无需额外 Mac 组件，也不改变现有语音触发键。本扩展不录音、不提供语音识别。

开启后，详情浏览时直接打字也会进入评论；编辑字段时先按 OK。菜单只控制评论显示，收起后仍可直接用麦克风追加下一段；已经在评论输入框内时，输入法继续原生输入。正在接收的语音会阻止切换记录和提前发送。写入失败时，原文保留在当前页，可复制、核对后重试或清空接收草稿；不会自动发送评论。

先在虚构演示表验证完整流程，尤其检查识别中修正、已有草稿追加和松开后结束。若输入法输出方式不同，请先关闭语音接入，保留原生输入操作并反馈版本与复现步骤。

## Mac 全屏

TV 会进入 Chrome 窗口全屏。如果仍能看到标签页和地址栏，在 Chrome「显示」菜单取消「在全屏模式下始终显示工具栏」。再按 TV 会明确退出当前窗口全屏，其他会议标签页不会阻止这次主动退出。会议模式自动收起数据表侧栏并隐藏文档顶部栏，退出恢复本页原来的状态。刷新后会在飞书侧栏加载完成时重新收起，并保留进入会议前的展开或折叠状态。网站会话存储被浏览器限制时，当前页面仍可操作；刷新后的偏好恢复可能不可用。

## 更新

本地扩展更新时，覆盖原文件夹，去扩展管理页点击「重新加载」，再刷新飞书页面。不要删除原扩展，否则可能失去本机设置。

v1.5.0 保留旧版本的更名与配置兼容；项目名称为「多维表格控制助手」，保留现有自定义键，并兼容旧名配置文件。音量仍用原 Control + Shift + = / − 和固定步长；菜单只展开或收起评论，按 OK 进入输入；输入框激活时返回键始终只删除，取消旧版空框双击退出。已加载的本地目录请保持原路径，以免 Chrome 将它识别为另一份扩展。

从本地版切换到商店版时，它们可能拥有不同的扩展 ID。本地版先导出配置，在商店版导入；Home 与电源的 Chrome 快捷键需要分别设置。不要同时启用两份扩展操作同一表格。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| GitHub 上电源键没反应 | 使用顶部的跨标签页电源命令，检查 Chrome 和映射软件键值一致；Chrome 要获得焦点。 |
| Home 没有返回 | 先在一个多维表格中开启会议。Home 只找仍在会议中的标签页。 |
| 输入时方向键不切记录 | 这是预期行为：方向键用来移动光标和选词。评论中可用菜单键收起，或用默认 Esc 单独退出输入；空框不会通过返回键退出。 |
| 正文中的网址没有单独落焦 | 仅适配类型为“超链接”的字段，避免正文产生大量焦点。 |
| 缩放连续按没有变化 | 先确认未到 50% / 250% 边界，并在按键检测区检查连续输入。若慢速正常而快速按不完整，请检查映射软件的双击识别、连发或抑制设置；本次使用者已在映射软件中解决。 |
| 麦克风没有自动展开评论 | 开启语音接入并进入会议中的记录详情；在输入法完成识别后检查。Fn 按下瞬间不会展开。 |
| 更新后没有新选项 | 重新加载扩展、重新打开设置页，并刷新飞书页面。 |
| 配置导入后 Home / 电源不一致 | 这些命令由 Chrome 保存，不在扩展的导入导出范围内。 |
